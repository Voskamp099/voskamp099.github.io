# Raelynn — 项目与笔记

[English](README.md) · [简体中文](README.zh-CN.md)

个人项目与技术博客，发布到 **https://voskamp099.github.io/**。

沿用所提供 HTML 模板的奶油色底、橙色点缀和等宽字体，把页面整理为文章、项目和关于三个区域。浅色背景保留稀疏的淡点阵，深色背景使用纯色。

- 中英文切换、深浅色切换，偏好保存在浏览器。
- 文章搜索与分类，手机导航，键盘焦点和减少动态效果支持。
- 一个项目对应一篇完整记录，调试过程作为文章内的章节；每篇文章有独立地址，提供站点地图和 404 页面。
- RSS 保留给订阅阅读器自动发现，页面不显示直接打开 XML 的按钮。
- 文章用 Markdown 保存，构建后是静态 HTML，适用于 GitHub Pages。
- 不包含旧网站的简历、私有资料、数据库或后台管理入口。

## 本地查看

需要 Node.js 22 或更高版本，以及 Python 3。

```bash
npm ci
npm run build
npm run check
npm run dev
```

打开终端打印的本地地址。

## 添加文章

在 content/posts/ 中增加：

1. 一份 JSON 元数据，包含唯一 slug、日期、分类、标签与中英文标题、简介。
2. 中文和英文两份 Markdown 正文，并在 JSON 的 body 字段中填写文件名。

现有文章可以作为格式样例。修改后运行 npm run build 和 npm run check，提交并推送到 main。GitHub Actions 会自动构建并发布 dist/。

## 关键词库

所有文章的关键词都从 content/tag-library.json 里选，不要在文章 JSON 里直接写标签文字。

- 库里的每条关键词有 id、英文名、中文名和分组（platform / stack / method / topic / format）。
- 每篇文章固定 4 个关键词，数量由库里的 perPost 决定。
- 文章 JSON 的 tags 字段只写 id，例如 "tags": ["worldquant-brain", "quant-research", "automation", "ai-collaboration"]。
- 构建时会校验：出现库里没有的 id，或者数量不等于 perPost，npm run build 直接报错。
- 页面上的胶囊会按当前语言显示中文名或英文名，搜索同时匹配两种语言。
- 研究类文章的关键词描述的是工作本身：领域（视频推理、AI）、工作类型（基准评测、多模型、反事实）
  和写作形式（研究记录、评测与审核）。只描述内部流程的关键词不要放到文章上。

需要新关键词时，先在 tag-library.json 里加一条，再在文章里引用。

## 文章写作规范

- **标题用「名称：说明」的结构。** 正经产品类文章先写项目专有名（PetAssistant、AlphaForge），冒号后
  一句话说明；中英文保持同一个结构，英文里冒号后用小写开头，例如
  "AlphaForge: alpha research with an agent"。
- **正文第一次提到项目时把名字交代出来**，不要让标题里的名字在正文里没有出处。
- **关键词胶囊到处用同一种带框样式**，文章页标题下面那一行和样本页的关键词都用首页的胶囊样式，
  读者在哪看到的形状都一样。
- **鼠标停在文章卡片上时只有标题变红**，关键词保持原样，不加悬停样式。
- **slug 保持稳定**，链接发出后不改；文章合并时在 scripts/static-pages.mjs 里补一条跳转。

## 分类与筛选条

每篇文章的 JSON 带一个 `categories` 数组。首页的筛选条由实际用到的分类自动生成，所以新增一个
分类只需要改文章 JSON 和 scripts/build.mjs 里的标签表。

- `research` 留给研究类文章。项目类文章保留自己的分类，卡片上会用一个小标签显示第一个分类。
- 分类只出现在卡片标签和筛选条里，正文不再重复。

## 图片与视频

- 图片放在 assets/ 下，用根相对路径引用，例如 `/assets/research/counterfactual/<name>.jpg`。
- 正文里可以只写一行 `%%VIDEO:/assets/.../true.mp4|/assets/.../counterfactual.mp4%%` 来嵌入一段或多段
  视频，构建时会把它变成一排播放器。Markdown 渲染器会转义原始 HTML，所以这个请求必须以纯文本
  形式传递。
- 视频要小：宽度缩到 512 像素，每段控制在 1 MB 以内。

## 样本页

样本页是独立的一页，不塞在文章里。文章讲方法与经验，样本页放产物：每个任务一条、每个生成器一条，
可以单独分享。

- 清单放在 content/v2v-task-samples.json 和 content/counterfactual-samples.json，由 scripts/build.mjs
  渲染。每条有 id、名称、模态或现象标识、中英文一句话说明、来源数据集、授权和引用方式。
- /sample-of-work/ 是目录，不是一页很长的清单。目录行的排版跟 writing 那节的列表一样：左边一个编号，
  一个胶囊标签，一个标题，一行说明，然后跳出去。每条样本点进去是它自己的一页：任务
  /sample-of-work/task-<编号>/，反事实生成器 /sample-of-work/generator-<标识>/，480 号任务的附录
  /sample-of-work/appendix-task-480/。
- 目录页上要直接看得到生成器那一节；只给一个跳转链接的不算一节。
- 两种模态对读者写全称：Video to Video 与 Reference Video to Video，缩写不出现在读者可见的正文里。
- 每条都要有中文任务名和中文提示词，跟英文版并排，因为读者先看中文页。
- 任务条目给出输入视频、目标视频和提示词；参考视频到视频的任务另外给出参考素材，参考素材单独占一
  行，标在输入与目标这一对之上。
- 页面上的所有片子用同一个框显示，参考素材和输入片子看起来是一回事，画面也不会被裁掉。
- 生成器条目给出真值与反事实并排的两条片子，以及现象标识。
- 页面不写任务是否完成、是否通过、是否待办。
- 每个任务条目自带一个"同时播放"，只放这一条任务的片子；页首留一个"全部暂停"。

### 媒体规则

- 服务器允许就用原始画质。GitHub Pages 按原样分发文件，所以片子保持原始分辨率，不为了网页再压小；
  只改容器（faststart），或者在浏览器解不了原格式时才改像素格式。
- 每条片子配一张封面图，播放前先显示真实画面。
- 不允许再分发的画面不发布，那一条只给提示词与任务定义，并写明原因。
- 视频放在 assets/v2v-samples/（任务）和 assets/generator-samples/（生成器），H.264、yuv420p、
  faststart、不带音轨。

### 授权规则

- 发布任何一帧之前先确认来源数据集的授权。每条都写明授权、授权链接和可直接使用的引用方式。
- 允许再分发的来源（Apache-2.0、MIT、CC BY、CC BY-SA、公有领域）按其要求标注后发布。
- 非商用来源（CC BY-NC）在发布时把非商用条款一并写明：页面本身不是商业产品，但这个条款对任何
  再使用者仍然有效。
- 限制再分发的来源、没有可再分发授权记录的图库素材，以及授权没有记录的来源，一律不发布画面。

## 设计与模板

- 站点的配色写在 assets/site.css 开头的 CSS 变量里。换一套 template 就是换这些变量的值，再加几条体现这套
  template 性格的组件规则（圆角、边框、顶栏）。
- 新 template 上线前先在本地搭出整站预览再看，不是只看一页。预览放在仓库外，用 http://127.0.0.1:4177/
  提供。
- 每套 template 在预览里都是一份构建产物的拷贝，模板样式表挂在最后，比较的就是真实页面换了配色后的样子。
- 配色和排版分开看：先定配色，再定排版，换排版不带着换配色走。

## 研究类文章要写什么

- 每个生成器、每个任务给一条真实样本，而不是只讲想法。
- 数据集的工作要列出所有拿到正式审核通过的任务。只过 Gate B、还没走完 Gate C 的同样算数，也照样
  留在列表里。
- 公开页面不写每个任务走到哪一步。闸门与交付状态属于内部信息，读者看到的是任务定义、样本和方法。
- 第三方源素材的授权不允许再分发时留在团队存储里；文章公开契约、流程和量级数字，画面放在样本页
  上（授权允许时），授权不允许时不放。

首次发布需要在仓库 Settings → Pages 中选择 GitHub Actions；已经启用的仓库无需重复设置。

项目使用一个小型 Node.js 构建脚本和 markdown-it，没有应用服务器或数据库。源码仓库是公开的，草稿和个人材料不要放进来。
